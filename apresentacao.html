01A ideia

Por que isso existe.

O problema

Cada pessoa usa uma IDE e um assistente de IA diferente (VS Code + Copilot, Cursor, Claude Code…). Sem um padrão central, as regras de qualidade e — o mais grave — as regras de segurança clínica divergem entre repos e nem chegam ao agente.

A solução

Você escreve a regra uma vez, em markdown neutro. O toolkit gera automaticamente o formato de cada IDE, para cada repo. Mudou a regra? Muda num lugar só e propaga para os 3 ambientes e todos os repositórios.

02Como funciona

Da fonte neutra ao PR em cada repo.

source/regras + skills (markdown)
→
sync.tsgera por IDE
→
build/<repo>Cursor · Claude · Copilot
→
distribute.ts1 PR por repo

Toda a lógica de formato fica isolada em emitCursor / emitClaude / emitCopilot. Se um formato de IDE mudar, ajusta-se só ali e roda o sync de novo.

03O que cada IDE recebe

A mesma regra, três formatos.

IDEArquivos gerados
Cursor.cursor/rules/*.mdc
Claude CodeCLAUDE.md + .claude/skills/
GitHub Copilot.github/copilot-instructions.md + instructions/ + prompts/

05Para a equipe

Como isso te afeta no dia a dia.

  • As regras chegam sozinhas no seu repo: ao dar merge no PR do ai-toolkit, você ganha .cursor/rules, CLAUDE.md e as instruções do Copilot — seu assistente de IA já passa a seguir o padrão.
  • Não edite os arquivos gerados à mão. Eles são saída automática; a próxima sincronização sobrescreve.
  • Para criar ou mudar uma regra: edite source/rules/ ou source/skills/, rode pnpm sync e confira em build/.
  • Para publicar: pnpm distribute abre 1 PR por repo com as regras atualizadas.
  • Adicionar uma IDE nova (ex.: Windsurf) é uma função emit + uma linha no config. A fonte neutra não muda.
pnpm install
pnpm sync                 # gera os adaptadores para todos os repos
pnpm sync auth-service    # só um repo
